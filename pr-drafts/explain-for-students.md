# 小さな基板で DOOM を動かして、その変更を NuttX に送る話

やさしく書いた説明です。むずかしい言葉は、最後の「ことば集」にあります。

## 1. 何をしたの?

**とても小さなコンピュータ (Spresense) で、ゲームの DOOM を動かしました。**

そして、そのために書き足した部分を、**NuttX (ナットエックス) という OS の本家 (apache/nuttx)** に「取り入れてください」とお願い (= PR) する準備をしました。

- Spresense: ソニーの小さな基板です。メモリ (作業机の広さ) は 1.5MB だけです。スマホの1000分の1くらいです。
- DOOM: 1993年のゲームです。昔のパソコンでも動いたので、小さな機械でも動かしやすいです。
- NuttX: 小さな機械のための OS です。Windows や Android の、とても小さい仲間と考えてください。

## 2. 動かすために足りなかったもの

DOOM を動かすには、3つの部品が要ります。**目 (画面)・手 (キー入力)・机 (メモリ)** です。

| 部品 | 状況 | どうしたか |
|---|---|---|
| 目 (画面) | Spresense には画面用の部品はあるが、DOOM が「絵を描く場所」として使える形になっていなかった | NuttX にもともとある「変換部品」を**スイッチを入れるだけ**で使った。新しいコードは書いていない |
| 手 (キー入力) | キーボードがつながらない | PC のキー入力を、**USB ケーブル (シリアル) 経由**で受け取る機能を書いた |
| 机 (メモリ) | 狭すぎて、ゲーム中に机から物がこぼれて止まった | 場所を取る「画面切り替えの演出」を**切れるスイッチ**を作った |

## 3. PR を3つに分けた理由

NuttX のルールで、**「1つの PR には、1つのことだけ」**と決まっています。
たくさんの人が見て確かめるので、1つが小さいほど、早く安全に確認してもらえるからです。

だから、次の3つに分けました。

### PR ① キー入力 (nuttx-apps、約270行)

- **やること:** PC のキーボードで、DOOM を操作できるようにする。
- **たとえ:** ゲームのコントローラーが無い機械に、「PC のキーボードを、コントローラー代わりにつなぐ変換アダプター」をつける感じです。
- **操作:** W/A/S/D か矢印で移動、J で撃つ、E でドアを開ける、Q でメニュー。
- **ひと工夫:** PC のキーボードは「押した」ことは送ってくれますが、「離した」ことは送ってくれません。そのままだと、キャラクターが歩きっぱなしになります。そこで、**最後に押されてから0.25秒たったら、自動で「離した」ことにしています。**
- **安全性:** 初期状態は OFF のスイッチなので、ほかの人の設定には、何も影響しません。

### PR ② 画面切り替えの演出を切る (nuttx-apps、約11行)

- **「画面切り替えの演出」って?** DOOM で、ゲームを始めるときや、面が変わるときに、**古い画面が、ドロドロと下に溶け落ちていって、その下から新しい画面が現れる**、あの有名な演出です。英語では「screen wipe (スクリーン・ワイプ)」や「melt (メルト)」と呼ばれます。
- **やること:** この演出を、OFF にできるスイッチを足す。OFF にすると、溶けずに、パッと新しい画面に切り替わります。
- **理由:** あの演出は、**画面1枚分の大きな紙を、2枚も作業机に広げます。** 机が狭い Spresense では、置き場所がなくなって、ゲームが止まりました。
- **たとえ:** 机が狭いので、「資料を2枚広げる派手なプレゼン」はやめて、「次のページに、そのまま切り替える」ようにした感じです。
- **安全性:** これも、初期状態は OFF のスイッチです。

### PR ③ Spresense 用の設定と説明書 (nuttx、約150行)

- **やること:** 「この設定を選べば、Spresense で DOOM が動く」という**設定のセット**を足す。説明書も足す。
- **たとえ:** 料理のレシピ集に、「Spresense 用 DOOM」のレシピを1ページ足す感じです。材料 (部品のスイッチ) と手順が書いてあります。
- **注意:** このレシピは、PR ①と②で作ったスイッチを使います。だから、**①②が先に取り入れられる必要があります。**

## 4. 変更は、大きいの?

**「ふつうくらい」と考えています。ただ、減らせる所はあります。**

行数の内訳です。

- PR ①の `i_input.c` の260行は、**空行33、コメント69、波かっこだけの行40、実際の処理は約118行**です。NuttX の書き方のルールで、1つの処理が縦に長くなります。
- PR ③の設定ファイル111行は、**自動で作られるファイル**です。土台 (`spresense:lcd`) との違いは、**19行だけ**です。
- PR ②は、ゲーム本体のファイル (`d_main.c`) の変更が、**たった2行**です。

### 他の人のコードを持ってきたの?

**いいえ。** 外のプログラムをコピーしてはいません。

- **お手本にしたもの:** DOOM の同じファイルにすでにある「キーを変換する部分」の書き方です。同じ形に合わせて書きました。
- **もともとあった部品を使ったもの:** 画面の変換部品 (`lcd_framebuffer`)、ファイルを送る仕組み (`rz`)、メモリを節約するスイッチ (`STATIC_SCRNBUF`) です。
- **AI の支援:** コードは、AI (Claude) の支援を受けて書きました。NuttX のルールで、コミットのメッセージに `Assisted-by:` と明記してあります。

### もっとシンプルにできる?

できます。PR ①の中の「どのキーを何に変えるか」の部分 (いまは約100行) を、**表にまとめる形**に書き直せば、**30〜50行ほど短く**なる見込みです。

ただし、いま出す準備ができているものは、実機で動作確認ずみです。書き直すと、**署名を付け直し、もう一度、実機で確認する**必要があります。だから、いまは「動いているものを、そのまま出す」案もあります。

## 5. まだ確認していないこと

正直に書いておきます。

- 実際に遊ぶところは、**確認できました**。新しいゲームを始めて、前進、後退、左右の回転、撃つ、使う、がすべて効きました。
- **なめらかさ:** 測りました。ゲーム中は、**1秒に19〜20コマ**くらいです (元のゲームは、1秒に35回、状態を更新します)。
- 小さな DOOM (1レベルだけ) で、動きました。**本物のお試し版 (約4.2MB) は、Spresense のフラッシュ (4MB) に、そもそも入りません。** 大きな WAD を使うなら、SDカードが要ります (試していません)。
- 説明書は、追加したページが**正しく出力されること**を確認しました。

## 6. ことば集

- **OS:** 機械を動かす基本のソフトです。
- **PR (プルリクエスト):** 「この変更を、取り入れてください」というお願いです。
- **コミット:** 変更を1つの区切りとして、記録したものです。
- **署名 (Signed-off-by):** 「この変更を、私が責任をもって出します」という印です。人間だけが付けられます。
- **フレームバッファ:** 画面に出す絵を、いったん置いておく場所です。
- **シリアル:** 1本の線で、文字をやりとりする方法です。USB ケーブルで使っています。
- **WAD:** DOOM のデータ (マップや絵) のファイルです。ゲームのプログラムは入っていません。
- **メモリ (RAM):** 作業机の広さです。広いほど、一度にたくさん広げられます。

## 7. 変更したファイルと、その中身 (①②③)

ここからは、1つ1つのファイルが、何をしているかを説明します。

### ① キー入力 (2ファイル、合計 +270行)

| ファイル | 増えた行 | 中身 |
|---|---|---|
| `games/NXDoom/Kconfig` | +10 | 「UART入力を使うか」のスイッチ (初期状態は OFF)。うち5行は、スイッチの説明文です。 |
| `games/NXDoom/src/i_input.c` | +260 | 本体。次の部品でできています。 |

`i_input.c` の部品です。

- **押されているキーの記録欄 (`g_held`):** 8個まで覚えられます。「どのキーを、いつ離したことにするか」を持っています。
- **`uartkbd_now`:** 今の時刻を返します (ミリ秒)。
- **`uartkbd_hold`:** 押されたキーを、記録欄に書きます。同じキーが続けて届いたら、「離す時刻」を先に延ばします。記録欄がいっぱいなら、そのキーは無視します。
- **`uartkbd_decode`:** 届いた1文字を、DOOMのキーに変換します。`w` なら「上」、`j` なら「撃つ」です。矢印キーは、3文字の並び (ESC, `[`, `A` など) で届くので、それも解釈します。
- **`get_uartkbd_event`:** ゲームが呼ぶ窓口です。「離す時刻が来たキー」を先に知らせて、次に、新しい文字を読みます。
- **もともとあった関数 `get_kbd_event`:** 「UART入力が有効なら、そちらを使う」という2行を足しました。

`i_input.c` の260行のうち、実際の処理は約118行です。残りは、コメント (69行)、空行 (33行)、波かっこだけの行 (40行) です。

### ② 画面切り替えの演出を切る (2ファイル、合計 +11行)

| ファイル | 増えた行 | 中身 |
|---|---|---|
| `games/NXDoom/Kconfig` | +9 | 「演出を切るか」のスイッチ (初期状態は OFF)。説明文を含みます。 |
| `games/NXDoom/src/doom/d_main.c` | +2 | 演出の準備をする部分を、スイッチで囲みました。 |

`d_main.c` の変更は、この形です (`★` の2行が、足した行です)。

```c
★ #ifndef CONFIG_GAMES_NXDOOM_NOWIPE
  if (gamestate != wipegamestate)   // 画面が切り替わるとき
    {
      wipe = true;
      wipe_start_screen(...);       // 演出の準備 (大きな紙を作る)
    }
  else
★ #endif
    {
      wipe = false;                 // スイッチが ON のときは、いつもここだけ通る
    }
```

スイッチを ON にすると、演出の準備を飛ばして、いつも「演出なし」になります。

### ③ Spresense 用の設定と説明書 (3ファイル、合計 +151行)

| ファイル | 増えた行 | 中身 |
|---|---|---|
| `boards/arm/cxd56xx/spresense/configs/nxdoom/defconfig` | +111 | 「Spresenseで DOOM を動かすレシピ」です。 |
| `Documentation/platforms/.../spresense/index.rst` | +25 | Spresense のページに、この設定の説明を足しました。 |
| `Documentation/applications/games/nxdoom/index.rst` | +15 | DOOM のページに、①②の2つのスイッチの説明を足しました。 |

#### ③は、コメントばかり?

**いいえ。** 設定ファイル (111行) の内訳です。

- `#` で始まる行は、**12行だけ**です。冒頭の注意書きが7行で、残りの5行は「このスイッチは OFF」という行です。この5行も、設定そのものです。
- 残りの**99行は、すべて設定の値**です。
- ドキュメントの40行は、説明書の文章です。

#### 設定は、何を参考にして、どこを Spresense 向けに変えたの?

**出発点 (土台):** Spresense にもともとある `lcd` という設定です。ディスプレイ (ILI9340)、SDカード、USBなどが、すでに入っています。99行のうち、**80行は、この土台のままです。**

**お手本:** すでに DOOM が動いている別のボードの設定 (`linum-stm32h753bi` の `nxdoom`) と、DOOM 自身の設定ファイル (`Kconfig`) です。「DOOM を動かすために、最低限、何のスイッチが要るか」を、そこで確かめました。

**土台に足した19行** です。

| スイッチ | 何のため | どこから? |
|---|---|---|
| `ALLOW_GPL_COMPONENTS`、`CRYPTO`、`LIBC_LOCALE` | DOOM が動くための前提です。 | DOOM の `Kconfig` の「前提条件」と、ほかのボードに共通 |
| `DRIVERS_VIDEO`、`VIDEO_FB` | 画面を `/dev/fb0` として使います。 | ほかのボードに共通 |
| `LCD_FRAMEBUFFER` | ILI9340 を、DOOM が絵を描ける形に見せます。 | **Spresense向け。** NuttX の既存部品を ON にしました |
| `GAMES_NXDOOM`、`STACKSIZE=16384`、`STATIC_SCRNBUF` | DOOM 本体と、メモリの使い方です。 | Linum と同じ値 (`16384` が最小かは、確かめていません) |
| `KBDPATH=/dev/console` | キーを、シリアルコンソールから読みます。 | **Spresense向け** |
| `UARTKBD` | 上の入力方法を使います。 | **Spresense向け** (PR ①) |
| `NOWIPE` | 画面が溶けて切り替わる演出 (メルト) を切ります。 | **Spresense向け** (PR ②) |
| `PREFDIR=/mnt/spif` | 設定とセーブを、本体のフラッシュに置きます。 | **Spresense向け** |
| `SYSTEM_ZMODEM` ほか4つ | WAD を、PC から送ります。 | **Spresense向け。** 数値は、試して決めました |
| `UART1_RXBUFSIZE=8192` | 受信の取りこぼしを防ぎます。 | **Spresense向け。** 試して決めました |

**わざと取らなかったもの** です。Linum 専用の設定で、Spresense には合わないためです。

- `FB_CMAP`、`FILLSCREEN`、`ROWSTAGE`: STM32 の画面向けの高速化です。
- `USBHOST`、`HIDKBD`: USB キーボードを使う設定です。Spresense は、USB キーボードをつなげません。

**正直に書いておくこと:** 土台の80行には、DOOM と関係ないもの (たとえば、USBで PC につなぐ設定) も含まれます。`lcd` 設定が、もともと持っているものです。動作確認ずみの土台を、そのまま使うほうが安全なので、減らしていません。
